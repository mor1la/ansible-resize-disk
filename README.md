# Disk Migration to a Smaller Disk with Ansible

Проект предназначен для переноса данных со старого диска на новый диск меньшего размера с последующим переключением точки монтирования на новый диск.

## Подготовка диска с помощью Cldb

Изначально предполагалось, что перед запуском Ansible новый диск будет создан и подключён к виртуальной машине с помощью библиотеки **Cldb** и скрипта `prepare_disk_migration.py`.

Пример команды:

```bash
python3 prepare_disk_migration.py \
  vmware \
  test-vm-ubuntu \
  --disk-name "Hard disk 2" \
  --new-size-gb 3 \
  --state-output migration_state.json \
  --execute
```

Параметры команды:

| Параметр | Описание |
|---|---|
| `vmware` | Используемый провайдер виртуализации |
| `test-vm-ubuntu` | Имя виртуальной машины, к которой подключается новый диск |
| `--disk-name "Hard disk 2"` | Имя исходного диска, данные с которого необходимо перенести |
| `--new-size-gb 3` | Размер создаваемого диска в GiB |
| `--state-output migration_state.json` | JSON-файл с состоянием миграции, который можно использовать на следующем этапе для отключения неиспользуемого старого диска |
| `--execute` | Выполняет запланированные изменения; без этого флага команда не применяет их |

После выполнения команды новый диск должен появиться на виртуальной машине как отдельный неподключённый к файловой системе диск. Ansible автоматически найдёт единственный непримонтированный диск указанного размера.

---

## Что делает плейбук

Плейбук `playbooks/migrate_disk.yml` выполняется для группы хостов `ubuntu` и последовательно:

1. Проверяет исходную точку монтирования `/data`.
2. Выполняет повторное сканирование SCSI-шин для обнаружения нового диска.
3. Находит единственный непримонтированный диск с размером `new_disk_size_gib`.
4. Создаёт на новом диске файловую систему `ext4`, если диск ещё не отформатирован.
5. Временно монтирует новый диск в `/mnt/new_disk`.
6. Останавливает работающие сервисы, кроме системных сервисов, необходимых для SSH, сети и работы Ansible.
7. Копирует данные со старого диска на новый с сохранением атрибутов файлов.
8. Создаёт резервную копию `/etc/fstab` в `/etc/fstab.bak`.
9. Обновляет `/etc/fstab` и монтирует новый диск в исходную точку `/data` по UUID.
10. Повторно запускает остановленные сервисы.

Старый диск плейбук не удаляет и не отключает от виртуальной машины. 

---

## Реализованные роли

| Роль | Описание |
|---|---|
| `disk_prepare` | Проверка исходного диска, поиск нового диска по размеру, создание файловой системы и временное монтирование |
| `stop_services` | Получение списка работающих сервисов и их остановка, кроме сервисов из `keep_services` |
| `data_copy` | Копирование данных со старого диска на новый с помощью `cp -a` |
| `disk_switch` | Резервное копирование `fstab`, переключение точки монтирования на UUID нового диска и сохранение конфигурации |
| `start_services` | Запуск сервисов, остановленных перед копированием данных |

## Настройка виртуального окружения Python

На Ubuntu/Debian при необходимости установите Python и модуль `venv`:

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
```

Перейдите в каталог проекта и создайте виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируйте его:

```bash
source .venv/bin/activate
```

После активации обновите `pip` и установите зависимости из `requirements.txt`:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Затем установите необходимые Ansible-коллекции из `requirements.yml`:

```bash
ansible-galaxy collection install -r requirements.yml
```

Проверить установленную версию Ansible можно командой:

```bash
ansible --version
```

---

## Требования

- Ansible установлен на управляющей машине.
- cистема использует `systemd`.
- Установлены коллекции `ansible.posix` и `community.general`, перечисленные в `requirements.yml`:

```bash
ansible-galaxy collection install -r requirements.yml
```

- Новый диск уже создан и подключён к виртуальной машине.
- В группе `ubuntu` файла `inventory.ini` указан нужный хост.
- Пользователь Ansible имеет доступ по SSH и может выполнять команды через `sudo`.

---

## Настройка SSH-доступа

Для автоматического запуска рекомендуется настроить SSH-аутентификацию по ключу, чтобы пароль SSH не запрашивался.

Если вход по ключу или `sudo` без пароля не настроены, при запуске можно использовать:

- `-k` — запросить пароль SSH;
- `-K` — запросить пароль для `sudo` (`become`).

## Пример inventory

```ini
[ubuntu]
test-vm-ubuntu ansible_host=192.0.2.10 ansible_user=ubuntu
```

Замените IP-адрес и пользователя на параметры своей виртуальной машины.

---

## Запуск плейбука

Пример запуска с запросом пароля SSH и пароля `sudo`:

```bash
ansible-playbook -i inventory.ini playbooks/migrate_disk.yml -k -K \
  -e "new_disk_size_gib=4"
```

Переменная `new_disk_size_gib=4` задаёт размер нового диска в GiB. Значение должно точно соответствовать размеру уже подключённого нового диска.

Если SSH-ключи и `sudo` без запроса пароля настроены, запуск выглядит так:

```bash
ansible-playbook -i inventory.ini playbooks/migrate_disk.yml \
  -e "new_disk_size_gib=4"
```

---

## Основные переменные

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `new_disk_size_gib` | Не задано | Обязательный размер нового диска в GiB; передаётся через `-e` |
| `old_mount_point` | `/data` | Исходная точка монтирования, данные из которой переносятся |
| `new_mount_point` | `/mnt/new_disk` | Временная точка монтирования нового диска |
| `filesystem_type` | `ext4` | Тип файловой системы нового диска |
| `mount_options` | `defaults` | Параметры монтирования, записываемые в `/etc/fstab` |
| `keep_services` | Задано в плейбуке | Список системных сервисов, которые нельзя останавливать во время миграции |

При необходимости значения можно переопределить при запуске:

```bash
ansible-playbook -i inventory.ini playbooks/migrate_disk.yml -k -K \
  -e "new_disk_size_gib=4 old_mount_point=/data new_mount_point=/mnt/new_disk"
```

## Проверка после миграции

После успешного выполнения плейбука можно проверить:

```bash
findmnt /data
df -h /data
sudo blkid
sudo systemctl --failed
```

Также рекомендуется выборочно проверить перенесённые файлы и перезагрузить виртуальную машину, чтобы убедиться, что новый диск корректно монтируется через `/etc/fstab`.

Старый диск можно отключить средствами Cldb или провайдера.


## Открепление диска с помощью Cldb

Изначально предполагалось, что перед запуском Ansible старый диск будет откреплен с помощью библиотеки **Cldb** и скрипта `detach_archived_disk.py`.

Пример команды:

```bash
python detach_archived_disk.py \
  --state /migration_state.json
  --execute
```
